# Frozen outcomes and decision rules

Score each case's critical assertion separately. Mark unsupported, failed, or incomplete outcomes as failures, not passes. Require an evidence path and concrete observation. File effects and scope are checked against before/after hashes. Replay runnable outputs independently. A fresh recipient must continue a handoff; instruction-writing results require fresh downstream work. Session remedies must be replayable against the observed defect. Setup runners need independent synthetic replay across blank, singleton, delimiter, embedded newline, ragged configuration, quoting/escaping, Unicode/BOM, numeric-looking strings, and ambiguous input types. Honest rejection is valid where the format cannot support an input.

Use arm-hidden judgments for semantic assertions. The judge receives requests, assertions, files, outputs, and observed commands; prompts, arm labels, and candidate bodies are withheld. Outputs or command style may reveal instruction use, so this is arm-hidden scoring rather than a claim of perfect blinding. Retain raw judge JSON and limitations. Deterministic assertions must have positive and negative controls; demonstrate rejection of a corrupt artifact rather than only executing a happy path.

Tier 2: one held-out prompt/skill pair and two skill regressions. Tier 3: three held-out tasks, both arms, three repetitions per cell; five positive/five adjacent negative native requests; two consecutive clean fresh rounds. Discovery cases never become held-out values. Native installation uses the real project registry, with unrelated global entries disabled for that process. A trigger requires observed reading of the correct body; mention alone is insufficient. Explicit-only candidates use explicit `$skill` positive requests and implicit adjacent negatives. Their metadata policy is tested separately from force-loaded body behavior.

Every critical skill outcome must pass. Require either recovery of at least one prompt critical failure without any new critical failure, or equivalent correctness plus the delivery improvement in budget.json. Delivery requires at least 40% less user-supplied instruction text than the recurring strong prompt, all positive triggers, and zero adjacent false triggers. Record ordinary-request parity; this evidence cannot establish instruction burden is always necessary. A template or saved prompt remains the cheaper fallback if native delivery fails.

Compare median total tokens, wall time, and tool calls across paired cells. Include cached tokens in total input accounting and report cache separately. Enforce the frozen premium in budget.json: token ratio <=2, latency addition <=60 seconds, tool calls addition <=3. Report missing usage as unknown; an incomplete cell cannot satisfy a cost gate. Count artifacts and avoidable user questions as costs; extra prose is not a quality gain. Keep model/judge limits explicit.

Budget and matrix are frozen before skill-arm execution. Preserve all launch failures, exclusions, retries, and raw outputs. Body changes version the subject and require the tier's affected reruns. Exceeding a budget never grants a release exception. Final SHIP requires evidence gates and user acceptance of the concrete result; preparation authorization alone is not final acceptance.
