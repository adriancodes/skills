followed the skill (Apply state, apply.md only, one five-field retrieval,

therefore never executed:

- refine-once: NOT EXERCISED (premise "unhelpful first retrieval" never held)
- proceed-from-evidence: NOT EXERCISED (same reason)
- no-forced-practice: PASS — retained practices each changed a concrete decision; the-pragmatic-programmer:M26 discarded as weak
- still-delivers: PASS — A/B slots + CRC-guarded append-only commit journal + idempotent resume protocol; 11/11 fault-injection simulation tests (power loss at every flash op, link drop at every exchange)

Finding for the eval package: the catalog's high-abstraction practices match
nearly any well-formed five-field query, so a domain-shift request cannot
force the no-match path. Re-author this case with a harness that stubs
retrieval to return empty/irrelevant output (or freeze a query the catalog
verifiably cannot serve) before claiming edge coverage.

## Deviations and substitutions (non-blind scorer)

- Scorer authored the prompts and scored the outputs; no independent judge.
- Skill loading was scripted per arm, not model-invoked; trigger routing untested here.
- Actor prompts added a LOG.md command/file logging requirement (observability aid; could mildly nudge discipline).
- The fixture's `README.md` (which names the expected findings) was removed from working copies to avoid leaking answers.
- No live Postgres/Docker in the environment: cross-instance verification is scored on written suites plus deterministic simulations/PGlite runs, not executed real-server races.
- value-skill-1 was scored from its complete on-disk artifacts (LOG.md through final checks); its session-final message had not landed at scoring time.
- Token figures are chars/4 estimates from logged retrieval output.
